# Slides2Grades

[![tests](https://github.com/mdue1337/Slides2Grades/actions/workflows/tests.yml/badge.svg)](https://github.com/mdue1337/Slides2Grades/actions/workflows/tests.yml)

Tooling to turn lecture slides, recordings, and your own notes into a well-organized
Obsidian vault, plus generated practice questions and flashcards. This repo holds the
tooling only — your actual notes live in a separate Obsidian vault repo (e.g.
`note-vault`), never in here.

See `docs/superpowers/specs/2026-07-27-slides2grades-design.md` for the full design.

## Relationship to Notes2Knowledge

This repo only produces study material — it never checks whether you actually
learned it. [`Notes2Knowledge`](https://github.com/mdue1337/Notes2Knowledge) is a
separate, read-only companion tool that quizzes you on the notes this repo
generates (or has you explain them back), so GenAI stays a study partner instead
of doing the learning for you. The two repos share one contract: a per-course
`.courseinfo.yaml` file (schema documented in `STYLEGUIDE.md`) that tells
Notes2Knowledge which quiz style to use. Slides2Grades itself never reads that
file — it's documented here because this repo owns the vault's structure.

## Setup

Requires Python 3.10 or newer.

**Windows:** run the commands below in PowerShell, with `py` in place of
`python3` (e.g. `py -m pytest -v`, `py scripts\transcribe.py ...`). The skills
themselves run `python3 scripts/config.py ...`, so make sure `python3` also
works in your shell.

1. Copy the config template and point it at your vault:

   ```bash
   cp config.example.env config.env              # Linux/macOS
   Copy-Item config.example.env config.env       # Windows PowerShell
   ```

   Edit `config.env`:

   ```
   VAULT_PATH=/path/to/your/note-vault
   SEMESTER=3. Semester
   WHISPER_MODEL_SIZE=large-v3
   WHISPER_DEVICE=cuda
   ```

2. Install dependencies:

   ```bash
   pip install -r requirements.txt        # faster-whisper, for transcription
   pip install -r requirements-dev.txt     # pytest, for running the test suite
   ```

   On Windows, CUDA transcription also needs the cuBLAS/cuDNN runtime DLLs on
   `PATH` — see `docs/windows-cuda-setup.md`.

3. Set up automatic git backups for your vault — see
   `docs/note-vault-git-setup.md` for Obsidian Git plugin configuration, and
   `docs/note-vault-transcript-gitignore.md` for keeping raw transcripts out of
   version control.

## Vault layout

Every script and skill assumes this layout. It is the contract between this
repo and your vault; paths everywhere else in the repo are written against it.

```
<vault>/                                  # VAULT_PATH in config.env
├── _templates/topic-note.md              # Obsidian template for new topic notes
└── <Semester>/                           # e.g. "3. Semester" — SEMESTER in config.env
    ├── Progress.md                       # generated by scripts/progress.py
    └── <Course>/                         # e.g. "Software Engineering and Architecture"
        ├── Begreber.md                   # course glossary (cleanup, begreber-extract)
        ├── .courseinfo.yaml              # optional; read by Notes2Knowledge only
        ├── Literature/
        ├── Images/
        └── Week N/                       # e.g. "Week 3"
            ├── <NN - Title>.md           # the topic note, e.g. "05 - Observer Pattern.md"
            └── <NN - Title>/             # sibling folder, same name as the note
                ├── transcript_raw.md     # scripts/transcribe.py
                ├── exercises.md          # by hand
                ├── exam_questions.md     # review-notes
                └── flashcards.md         # flashcards-make
```

- A topic is named by its note filename without `.md` (`05 - Observer Pattern`),
  never by its week folder. Tools find the week by globbing `Week */`, so a
  topic name must be unique within its course.
- Week folders must be named `Week <number>`.
- The leading `NN` orders topics in `Begreber.md`; notes without one sort last.
- You create semester, course, week folders and notes by hand. The sibling
  folder and the files in it are created by the tool that writes them.

Defaults are Danish (`Begreber.md` is the glossary). Notes in any language
work; see **Language defaults** in `STYLEGUIDE.md` to rename the glossary.

## Workflow: which tool, when

| Step | Tool | What it does |
|---|---|---|
| New topic | (by hand) | Create `<Semester>/<Course>/Week N/` and the `<NN - Title>.md` note in Obsidian |
| After a lecture recording | `scripts/transcribe.py <audio> <course> "<NN - Title>"` | Runs faster-whisper locally, writes `transcript_raw.md` into the note's sibling folder. The note must already exist; semester comes from `SEMESTER` in `config.env` or `--semester` |
| After transcribing | `lecture-enhance` skill | Merges the transcript into the note, marked `[FROM LECTURE]` |
| After slides are posted | `slides-enhance` skill | Adds what slides cover that notes miss, flags contradictions |
| When a note has got long | `cleanup` skill | Rewrites the note down to note level and rebuilds its glossary section. Destructive; git is the undo |
| To refresh only the glossary | `begreber-extract` skill | Rebuilds a topic's section of `<Semester>/<Course>/Begreber.md`. Rewrites that section; git is the undo |
| Closer to exam time | `review-notes` skill | Generates exam-style questions into `exam_questions.md` |
| Any time | `flashcards-make` skill | Generates spaced-repetition cards into `flashcards.md` |
| Any time | `scripts/progress.py "<Semester>"` | Regenerates `<Semester>/Progress.md`, showing which pipeline steps each topic still needs |

All skills are run manually, one at a time, from within Claude Code — there's no
auto-chaining pipeline.
